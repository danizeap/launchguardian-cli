# LaunchGuardian CLI v0.1.0 — MVP

LaunchGuardian CLI v0.1.0 is the first MVP release of a local secure-shipping scanner for SDD+ projects. It validates LaunchGuardian Framework files, runs local defensive scanner checks, normalizes findings, and produces launch-focused reports.

Tag: `v0.1.0`

## What's Included

- LGF validation.
- Project and framework scan modes.
- Gitleaks integration for local secret scanning.
- Semgrep integration for local static code security scanning.
- Trivy integration for local dependency, filesystem, container, and IaC scanning.
- Native Frontend Exposure scanner.
- Native API Surface scanner.
- `launchguardian.yml` config support.
- Markdown and JSON reports.
- Normalized findings output.
- GitHub Actions CI templates.
- Sample reports from the vulnerable demo app.
- Vulnerable demo app support for calibration and onboarding.

## Safe-Use Boundaries

- Local-only scanning.
- Owned repos only, or repos where you have explicit permission to assess.
- No active web scanning.
- No offensive exploitation.

LaunchGuardian findings are defensive review signals. They should be reviewed by humans before remediation, acceptance, or launch decisions.

## Known Limitations

- External scanners must be installed locally or in CI.
- No SARIF output yet.
- No PyPI package yet.
- No ZAP/staging scan yet.
- Heuristic findings require review and may include false positives.

## Quickstart

For framework, template, or tool repos:

```bash
python -m launchguardian.cli scan --target . --framework-mode
```

## Project Scan

For projects with LGF files:

```bash
python -m launchguardian.cli scan --target .
```

## CI

Use the workflow templates in:

```text
templates/github-actions/
```

The strict template is intended for onboarded projects with approved external scanner installation steps. The non-strict template is for early adoption.

## Demo

The `launchguardian-demo-vulnerable-app` repo is intentionally vulnerable and local-only. It returns `BLOCKED` and demonstrates expected `frontend_exposure` and `api_surface` findings.
